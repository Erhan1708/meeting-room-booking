# Бронирование переговорной

Интерфейс бронирования одной переговорной комнаты в течение рабочего дня (09:00–18:00).
Выбор даты, просмотр броней дня, создание, редактирование и удаление броней.

- **Демо:** _ссылка на Vercel_
- **Затрачено времени:** _~N ч_

## Запуск

```bash
npm install
cp .env.example .env.local   # необязательно: по умолчанию mock включён
npm run dev                  # http://localhost:5173
```

| Скрипт                            | Что делает                                             |
| --------------------------------- | ------------------------------------------------------ |
| `npm run dev`                     | dev-сервер Vite                                        |
| `npm run build`                   | `tsc -b` + production-сборка                           |
| `npm test`                        | Vitest: правила, mock API, интеграционный сценарий 409 |
| `npm run lint` / `npm run format` | oxlint / oxfmt                                         |
| `npm run check-all`               | lint + проверка форматирования                         |

Деплой на Vercel: framework preset **Vite**, переменных окружения не нужно
(`vercel.json` отдаёт `index.html` для всех путей).

## Стек

React 19, TypeScript (strict), Vite, Redux Toolkit + RTK Query, Ant Design 6, Tailwind v4,
MSW (mock API), Vitest + Testing Library, oxlint/oxfmt.

## Архитектура

Feature-Sliced-подобные слои; у каждого слоя и модуля barrel `index.ts`,
импорт — из корня слоя (`from 'shared'`, `from 'modules'`). Алиасы прописаны в `vite.config.ts` и `tsconfig.app.json`.

```
src/
  main.tsx            точка сборки: включает MSW и dev-панель, если VITE_API_MOCKS=true
  app/                RootLayout (StrictMode › ErrorBoundary › Store › Ant › Routes), ErrorBoundary
  routes/             дерево маршрутов (одна страница + редирект)
  widgets/AppShell/   шапка и layout страницы
  modules/Bookings/
    model/            типы Booking, BookingInput, OfficeNow
    lib/              бизнес-правила и время — чистые функции + тесты
    api/              RTK Query эндпоинты, разбор ошибок брони
    components/       страница дня, лента дней, таймлайн, список, форма, просмотр
  shared/
    store/            Redux store, baseApi/baseQuery, normalizeApiError
    ant/ toast/ ui/   провайдер antd, тосты, ConfirmDialog/EmptyState/ErrorState
    global-modal/     единая модалка приложения через redux
    lib/ config/      cn, useQueryParams, env, стили и токены
  mocks/              mock-сервер (MSW): обработчики, хранилище, dev-панель
```

### Сетевой слой отделён от UI и заменяем

- Компоненты не знают про `fetch`, URL и HTTP-статусы — только хуки
  `useGetBookingsQuery`, `useCreateBookingMutation` и т. д. из `modules/Bookings/api`.
- Весь HTTP — в `shared/store/api` (`baseQuery`: базовый URL, таймаут) и описаниях эндпоинтов.
  Ошибки приводятся к `{ kind, message, code, fieldErrors, details }` в `normalizeApiError`.
- MSW перехватывает **настоящие** `fetch`-запросы на уровне Service Worker — приложение
  не отличает mock от бэкенда. Подключается только в `main.tsx`; импорт `mocks` из остальных
  слоёв запрещён правилом `no-restricted-imports` в `.oxlintrc.json`.

**Подключить реальный API:**

1. Контракт совпадает — задать `VITE_API_MOCKS=false` и `VITE_API_URL=https://api.example.com`.
   Код не меняется.
2. Отличаются форма данных или ошибок — добавить маппинг (`transformResponse`) в `bookingsApi.ts`
   и/или `normalizeApiError`. UI не трогается.

### Бизнес-правила

Правила — чистые функции в `modules/Bookings/lib/rules.ts`. Их используют и форма
(подсказки и недоступные варианты до отправки), и mock-сервер, который **заново проверяет всё**
и является источником правды. Клиентская проверка — только для удобства: UI всегда
корректно обрабатывает ответ сервера, даже если сам считал слот свободным.

### Обработка конфликта (409) и других ошибок

- **409** — форма остаётся открытой со всеми введёнными данными, сверху понятное сообщение
  («Это время только что заняли»), у поля «Начало» — какая бронь мешает. Список
  перезапрашивается автоматически: мутации инвалидируют кэш дня **и при ошибке**.
  Занятые варианты времени сразу гаснут в выпадающих списках.
- **422** — ошибки полей от сервера показываются у соответствующих полей.
- **404 / бронь уже началась** — сообщение, кнопка сохранения блокируется, список обновляется.
- **Сеть / 500** — сообщение в форме (данные сохраняются) или блок ошибки с «Повторить» на странице;
  если данные дня уже были загружены, показываются они с предупреждением.

Формат ошибки mock-сервера: `{ code, message, details?: { fieldErrors?, conflicting? } }`.

### Как воспроизвести конфликт

- **Dev-панель «Mock API»** (кнопка в левом нижнем углу): «Конфликт при следующем сохранении» —
  «другой сотрудник» занимает слот за мгновение до вашего запроса, сервер отвечает 409.
  Там же задержка сети (видно состояния загрузки/отправки), ошибка 500 и сброс демо-данных.
- **Две вкладки:** хранилище mock-сервера читает `localStorage` на каждый запрос, поэтому
  забронировать один слот из двух вкладок — настоящий конфликт.

## Принятые решения

| Вопрос                          | Решение                                                                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Часовой пояс                    | Фиксированный пояс офиса `Asia/Bishkek` для «сегодня» и «сейчас» — одинаково на клиенте и сервере, независимо от пояса браузера |
| Шаг времени                     | 15 минут (сервер тоже требует кратность шагу)                                                                                   |
| Частично прошедший слот сегодня | Округление вверх: в 10:10 первое доступное начало — 10:15                                                                       |
| Пересечения                     | Полуоткрытые интервалы `[start, end)`: 10:00–11:00 и 11:00–12:00 допустимы                                                      |
| Прошедшие брони                 | Только просмотр                                                                                                                 |
| Начавшиеся брони                | Только просмотр (нельзя изменить и удалить); сервер отвечает `422 BOOKING_LOCKED`                                               |
| Перенос на другую дату          | Разрешён, правила проверяются для новой даты                                                                                    |
| Название                        | Необязательное, до 100 символов, пробелы по краям обрезаются                                                                    |
| Прошедшие даты                  | Можно открыть и посмотреть брони, создание недоступно                                                                           |
| Хранение                        | MSW в браузере, данные в `localStorage` (в пределах одного браузера)                                                            |
| Выбранная дата                  | В URL (`?date=YYYY-MM-DD`) — переживает перезагрузку, ссылкой можно поделиться                                                  |
| Неделя                          | Начинается с понедельника                                                                                                       |

## UI и доступность

- **Выбор даты — лента дней как в календаре** (`WeekStrip`) на всю ширину блока:
  на десктопе видно две недели, на мобильном — одна.
  - Выбранный день — закрашенный круг, сегодня — обводка, дни с бронями подсвечены и отмечены
    точкой, выходные приглушены. Над лентой — видимый месяц (или диапазон месяцев) и ссылка
    «Сегодня», если сегодняшний день не виден.
  - Плавная горизонтальная прокрутка без жёсткой привязки к дням: тачпад, свайп, стрелки
    (плавно на неделю). По краям — мягкое затухание, чтобы частично видимые дни не выглядели обрезанными.
  - Лента бесконечна в обе стороны: у краёв достраивается ещё 8 недель без скачка прокрутки.
  - При открытии лента плавно доезжает до выбранного дня и ставит его по центру; так же —
    если дата сменилась извне (ссылка «Сегодня», `?date=` в URL) и день не виден.
    С `prefers-reduced-motion` — без анимации.
  - Наличие броней берётся тем же `GET /api/bookings?date=` — контракт не расширялся.
    Запрашиваются только видимые дни и неделя запаса с каждой стороны, ответы кэшируются
    RTK Query и переиспользуются при выборе дня.
  - У каждого дня подпись для скринридера («четверг, 8 октября, броней: 2»), `aria-pressed`
    у выбранного, `aria-current="date"` у сегодняшнего, видимый фокус с клавиатуры.
- Десктоп: таймлайн дня (клик по свободному месту — новая бронь с этим началом) + список.
  Мобильный: только список и кнопка «Забронировать».
- Список — основное представление для клавиатуры и скринридеров; таймлайн дублирует
  его визуально и скрыт из дерева доступности.
- Подписи у всех полей и кнопок-иконок, `aria-live` для смены даты и статуса обновления,
  сообщения об ошибках в `role="alert"`, ссылка «Перейти к содержимому», фокус в модалках — antd.
- Состояния: skeleton загрузки, пустой день, ошибка с повтором, фоновое обновление, отправка формы.
- «Сейчас» обновляется каждые 30 секунд — прошедшие слоты гаснут без перезагрузки,
  данные перезапрашиваются при возврате во вкладку (`refetchOnFocus`).

## Тесты

- `modules/Bookings/lib/rules.test.ts` — все бизнес-правила, границы, пояс офиса, расчёт недели.
- `mocks/handlers.test.ts` — контракт mock API: 201/400/404/409/422/500.
- `modules/Bookings/components/BookingsSection.test.tsx` — интеграционный сценарий 409:
  данные формы сохранены, сообщение показано, список обновлён.

- Подсветка конфликтующей брони на таймлайне после 409.
- Клавиатурная навигация по самому таймлайну (сейчас её роль выполняет список).
- Оптимистичные обновления — сознательно не стал: для бронирования важнее не показать
  пользователю то, чего сервер не подтвердил.

  вместо запроса на каждый день; не добавлял, чтобы не расширять контракт из ТЗ.
- Code-splitting antd (основной чанк ~1 МБ / 350 КБ gzip).
